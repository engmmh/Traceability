# UFUQ Branch Inspection — Supabase + GitHub

هذه النسخة تنقل **منطق نظام فحص فواتير الفروع** من Google Apps Script/Sheets إلى Backend Node.js مع Supabase PostgreSQL.

## ما تم الحفاظ عليه
- تسجيل دخول بكلمة مرور من متغير بيئة، وليس داخل الواجهة.
- تاريخ تشغيل يومي.
- رفع عدة PDF في عملية واحدة.
- استخراج كود الفرع وأكواد المنتجات.
- قواعد الأكواد الخاصة: 8000855 → 6000740 + 6000742، و8000854 → 6000741 + 6000742.
- وضع ✓ للمنتجات المطابقة في كل نموذج مرتبط بالفرع.
- تقرير صريح بالأكواد الموجودة في الفاتورة وغير الموجودة في قاعدة المنتجات.
- تحديث تواريخ مجموعة كاملة أو منتج منفرد، مستقلًا عن ✓.
- إضافة مجموعات ومنتجات من الموقع بدون تعديل JavaScript.
- مسح ✓ فقط مع بقاء المنتجات والتواريخ والمجموعات.
- عرض وطباعة النماذج.
- 12 نموذجًا جاهزة، لكن **ربط الفروع بالنماذج وربط المنتجات بالنماذج يجب استيراده من الشيتات الفعلية**؛ لم يتم اختراعه.

## نقطة مهمة جدًا: OCR
`pdf-parse` يقرأ PDF الذي يحتوي نصًا حقيقيًا. إذا كانت الفواتير عبارة عن صور/Scanned PDF، فهذه النسخة ستعطي رسالة واضحة ولن تدّعي نجاح الاستخراج. في الخطوة التالية نضيف OCR مناسب إذا كانت ملفاتكم تحتاجه.

## تشغيل محلي
1. انسخ `.env.example` إلى `.env`.
2. ضع بيانات Supabase.
3. نفّذ `schema.sql` داخل Supabase SQL Editor.
4. نفّذ `npm install`.
5. نفّذ `npm start`.
6. افتح `http://localhost:3000`.

## GitHub
ارفع محتويات هذا المجلد إلى Repository جديد. لا ترفع `.env` أو أي Service Role Key.

## قبل الإنتاج
لا نعتبر النظام بديلًا نهائيًا لـGoogle Sheets قبل:
- استيراد جميع المنتجات والأكواد والمجموعات.
- استيراد ترتيب المنتجات في النماذج الـ12.
- استيراد mapping الفروع ↔ النماذج من الشيتات، بدل التخمين.
- اختبار PDF حقيقية من كل الفروع.
- اختبار OCR إذا كانت الملفات ممسوحة ضوئيًا.
- اختبار الطباعة مقابل النموذج الورقي.
